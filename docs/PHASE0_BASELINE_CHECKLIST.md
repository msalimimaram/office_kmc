## 1. هدف و مرز این مرحله

هدف فاز صفر، اضافه‌کردن قابلیت‌های جدید محصول نیست. هدف، ایجاد یک نسخه مرجع قابل اعتماد از پروژه، اثبات سلامت کد و داده، بستن ریسک‌های حیاتی و آماده‌کردن مسیر پذیرش عملیاتی است.

تا پایان این مرحله:
- هیچ قابلیت محصولی خارج از اصلاحات لازم برای ایمنی و تثبیت به پروژه افزوده نمی‌شود.
- فرم‌ساز، گزارش‌ساز پیشرفته، توسعه مدل بیمه‌نامه/پوشش و یکپارچگی‌های بیرونی در صف باقی می‌مانند.
- ادعای «تست سبز» فقط با خروجی اجرای واقعی روی همان commit مجاز است.
- موفقیت تست محلی یا static review به‌تنهایی مجوز استفاده از داده واقعی نیست.
- پس از تکمیل تمام موارد اجباری، پروژه دوباره ممیزی می‌شود و نقشه راه فازهای بعدی از نو و بر اساس وضعیت واقعی طراحی خواهد شد.

## 2. قواعد حاکم بر اجرای چک‌لیست

1. تمام تغییرات مستقیم روی `main` ثبت شوند؛ شاخه جدید، PR و GitHub Actions ایجاد نشود.
2. قبل از هر بسته اصلاحی، commit مبنا و وضعیت فایل‌های محلی ثبت شود.
3. migration، seed، پاک‌سازی یا بازنشانی روی دیتابیس واقعی یا دیتابیسی که داده آن باید حفظ شود ممنوع است.
4. `seed_demo` یک فرمان یک‌باره برای دیتابیس محلی تازه و دورریختنی است؛ اجرای مجدد روی fixtureهای موجود باید fail-closed شود.
5. هیچ تست، migration، اسکنر، backup یا آزمون staging بدون خروجی واقعی به‌عنوان انجام‌شده علامت نخورد.
6. خطای تست با حذف assertion، تضعیف مجوز، bypass کردن Workflow gate یا خاموش‌کردن آزمون حل نشود.
7. همه خروجی‌ها، tracebackها، شناسه commit، محیط اجرا و تاریخ آزمون در بخش «ثبت اجرای فاز صفر» ثبت شوند.

## 5. دروازه خروج از فاز صفر

فاز صفر فقط زمانی بسته می‌شود که همه موارد زیر برقرار باشد:

1. کل تست‌ها روی commit نهایی سبز باشند.
2. check، migration consistency، schema verification و audit_workflows موفق باشند.
3. seed و preflight رفتار fail-safe اثبات‌شده داشته باشند.
4. ریسک‌های حیاتی RBAC/IDOR و محرمانگی بسته و تأیید امنیت دریافت شده باشد.
5. MFA و کنترل نشست به معیار مصوب برسد.
6. PostgreSQL، ClamAV، private media، backup/restore و زمان‌بندها در staging آزموده شوند.
7. تمام journeyهای الزامی با نقش‌های واقعی‌نما end-to-end قبول شوند.
8. اداره بیمه کرمان موتور و مسئول زیرساخت/امنیت تصمیم Go/No-Go را امضا کنند.

**تا پیش از تکمیل دروازه خروج، ورود داده واقعی و بهره‌برداری سازمانی مجاز نیست.**

## 6. پس از پایان این مرحله

پس از تیک خوردن تمام موارد بالا:
- یک snapshot نهایی از main و گزارش تست/امنیت/زیرساخت ثبت می‌شود.
- ممیزی مجدد فاصله محصول با سند جامع انجام می‌شود.
- اولویت‌های فازهای بعدی بر اساس شکاف‌های باقی‌مانده، وابستگی‌ها و ارزش کسب‌وکاری بازچینی می‌شوند.
- سپس فقط یک بسته اجرایی بعدی تصویب و آغاز می‌شود؛ توسعه موازی و پراکنده خارج از برنامه انجام نمی‌شود.
