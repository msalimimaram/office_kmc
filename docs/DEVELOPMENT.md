# استاندارد توسعه و بازبینی کد

## گردش کار پیشنهادی

1. مسئله و معیار پذیرش را در issue یا شرح تغییر مشخص کنید.
2. پیش از کدنویسی، اپ و مالکیت داده مرتبط را پیدا کنید.
3. تغییر را کوچک و متمرکز نگه دارید؛ رفتار موجود را بدون دلیل تغییر ندهید.
4. برای تغییر مدل، migration تولید و بازبینی کنید.
5. برای رفتار جدید تست بنویسید؛ مخصوصاً دسترسی نقش‌ها و tenant scoping.
6. تست‌ها و system check را اجرا کنید.
7. مستندات اپ و مستندات سراسری را در همان تغییر به‌روز کنید.
8. diff، secretها، فایل‌های ناخواسته و migrationها را پیش از commit بررسی کنید.

## قواعد کدنویسی

- نام‌گذاری واضح و سازگار با سبک Python/Django.
- مجوزها در سمت سرور؛ template صرفاً برای نمایش است.
- QuerySetهای محدود و مشخص؛ هرگز به ورودی کاربر برای تعیین tenant اعتماد نکنید.
- از `select_related`/`prefetch_related` در صورت نیاز برای جلوگیری از N+1 استفاده کنید.
- از ثبت کد ملی، شماره شبا، محتوای اسناد یا رمزها در log خودداری کنید.
- از داده ساختگی در تست استفاده کنید.
- هر تغییر وضعیت workflow باید actor، شرایط مجاز و رفتار خطا را مشخص کند.
- تغییر schema باید migration قابل بازبینی داشته باشد.

- [ ] مستندات به‌روز
- [ ] system check و تست‌ها
