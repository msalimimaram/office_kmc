# مشخصات بازطراحی رابط کاربری Office KMC

**نسخه:** 1.0 — 2026-11-10  
**مرجع:** پوسته Django server-rendered فعلی؛ بدون تبدیل پروژه به SPA.

## هدف تجربه

یک پورتال سازمانی حرفه‌ای، آرام، متراکم اما خوانا، سریع و کاملاً RTL برای عملیات بیمه. ظاهر باید مدرن باشد، اما اولویت همواره وضوح اقدام، مالکیت پرونده، مهلت، سطح محرمانگی و وضعیت گردش‌کار است.

## اصول طراحی

- فارسی و RTL در تمام breakpointها؛ استفاده از ویژگی‌های منطقی CSS مانند `margin-inline` و `padding-inline`.
- دسکتاپ: سایدبار راست‌چین با حالت باز/جمع‌شده؛ موبایل: drawer با کنترل صفحه‌کلید و focus trap.
- هدر شامل عنوان/مسیر صفحه، جست‌وجوی مجاز، اعلان‌ها، کنترل تم و منوی حساب.
- تم‌ها: روشن، تاریک و پیروی از سیستم؛ انتخاب کاربر حفظ شود. بدون flash روشن/تاریک هنگام بارگذاری.
- CSS custom properties معنایی برای background، surface، elevated surface، text، muted text، border، accent، success، warning، danger، focus و shadow.
- حالت focus قابل مشاهده، کنتراست WCAG AA، برچسب واقعی فرم، پیام خطای قابل فهم و پشتیبانی صفحه‌کلید.
- سایدبار فقط لینک‌هایی را نشان دهد که context processor مجاز کرده است؛ پنهان‌سازی UI هرگز جایگزین کنترل سمت سرور نیست.
- در عرض 360، 390، 430، 768، 1024 و 1440 پیکسل باید بدون overflow غیرضروری کار کند.
- احترام به `prefers-reduced-motion` و کاهش انیمیشن در صورت درخواست کاربر.
- فونت محلی/قابل میزبانی در محیط داخلی با fallback مناسب؛ عدم وابستگی حیاتی به Google Fonts/CDN.

## ساختار ناوبری پیشنهادی

1. خانه: داشبورد.
2. کارهای من: ارجاعات، کارهای تفویض‌شده، وظایف، اعلان‌ها.
3. عملیات بیمه: اشخاص/بیمه‌شدگان، درخواست‌ها، خسارت‌ها، قراردادها، دارایی‌ها.
4. اسناد و ارتباطات: اسناد، مکاتبات، اطلاعیه‌ها، ورود Excel.
5. مدیریت: فقط امکاناتی که context processor و مجوز سمت سرور اجازه می‌دهد.
6. حساب کاربر: پروفایل، تغییر رمز، تنظیم ظاهر و خروج.

نام و ترتیب نهایی گروه‌ها باید با مسیرهای واقعی و access flags موجود هم‌خوان شود؛ URL جدید یا permission ساختگی ایجاد نشود.

## معیار پذیرش UI

- [ ] تم روشن، تاریک و سیستم روی تمام صفحات پایه و فرم‌ها کار کند.
- [ ] انتخاب تم پس از refresh حفظ شود و در صورت شکست storage، صفحه قابل استفاده بماند.
- [ ] سایدبار در دسکتاپ جمع/باز و در موبایل باز/بسته شود.
- [ ] لینک‌های غیرمجاز در UI نمایش داده نشوند و URL مستقیم نیز سمت سرور رد شود.
- [ ] تمام فرم‌ها، جدول‌ها، badgeهای وضعیت، alertها، pagination و صفحات خالی در هر دو تم خوانا باشند.
- [ ] عرض موبایل 360px بدون اسکرول افقی کل صفحه قابل استفاده باشد؛ جدول‌های عریض فقط در wrapper خودشان scroll شوند.
- [ ] کنتراست متن و کنترل‌ها حداقل WCAG AA باشد.
- [ ] صفحه‌کلید، focus state و reduced motion بررسی شوند.
- [ ] پوسته در مرورگرهای پشتیبانی‌شده سازمان بدون CDN خارجی قابل بارگذاری باشد.
- [ ] هیچ رفتار کسب‌وکار، endpoint، مدل یا permission به‌خاطر بازطراحی بصری تغییر نکند.
