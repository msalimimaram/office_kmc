# اداره بیمه — سامانه یکپارچه مدیریت بیمه

این مخزن پروژه مستقل «اداره بیمه» است و هیچ وابستگی به پروژه GAMva ندارد. سامانه با Django، رابط فارسی/راست‌چین و نقش‌های سازمانی طراحی شده است.

## قابلیت‌های موجود در مخزن

- حساب‌های کاربری با نقش‌های مدیر سامانه، رئیس اداره، کارشناسان، نمایندگان شرکت‌های تابعه، بیمه‌شدگان، بیمه‌گر، مالی، حقوقی و حسابرس
- ساختار شرکت مادر/شرکت‌های تابعه و اطلاعات کارکنان و افراد تحت تکفل
- قراردادها، بیمه‌گران، رشته‌های بیمه و نسخه‌های اصلاح قرارداد
- خسارت‌ها، وضعیت ارزیابی/پرداخت و ثبت اعتراض
- درخواست‌های کارکنان، سطح محرمانگی، تخصیص به کارشناس و گردش وضعیت محدودشده
- وظایف داخلی با مهلت، اولویت، مسئول و گردش وضعیت
- ورود گروهی خسارت از Excel با پیش‌نمایش، کنترل مبالغ/تاریخ‌ها، کشف ردیف‌های تکراری و تأیید نهایی
- کتابخانه اسناد با کنترل دسترسی هنگام دانلود
- اطلاعیه‌ها و بخشنامه‌ها با مخاطب، شرکت هدف، زمان انتشار و پایان اعتبار
- ثبت دارایی‌های بیمه‌شده شامل خودرو، ملک، تجهیزات و مشخصات بیمه‌نامه
- دفتر مکاتبات تلفنی، ایمیلی، نامه‌ها و جلسات با پیگیری موعد و دسترسی محدود به شرکت/بیمه‌گر
- ثبت رویدادهای حسابرسی برای عملیات حساس و آزمون‌های رگرسیون اولیه

## راه‌اندازی محلی در Windows

نیازمندی‌ها: Python 3.11+، pip و در صورت استفاده از PostgreSQL، درایور مربوطه.

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env
python manage.py makemigrations accounts organizations insurance claims requests_portal tasks documents imports auditlog assets announcements correspondence
python manage.py migrate
python manage.py check
python manage.py test
python manage.py createsuperuser
python manage.py runserver
```

فایل `.env` در اجرای محلی به‌صورت خودکار خوانده می‌شود (وابستگی `python-dotenv`). مقدار `DJANGO_DEBUG=True` فقط برای اجرای محلی است. تنظیمات به‌صورت پیش‌فرض fail-closed هستند: برای استقرار سازمانی باید `DJANGO_DEBUG=False`، یک `DJANGO_SECRET_KEY` تصادفی و قوی، `DJANGO_ALLOWED_HOSTS` صریح و محدود و `DATABASE_URL` مربوط به PostgreSQL تنظیم شود؛ اگر تنظیمات اصلی محیط تولید ناقص باشد، برنامه متوقف می‌شود.

## قالب فایل اکسل خسارت

سرستون‌های اجباری: `claim_number`، `national_id` و `service_type`.

سرستون‌های اختیاری: `service_date`، `registered_date`، `requested_amount`، `assessed_amount`، `payable_amount`، `paid_amount` و `payment_date`. قالب تاریخ `YYYY-MM-DD` است. مبالغ منفی/غیرعددی، تاریخ نامعتبر، شناسه خسارت تکراری و کد ملی مبهم در چند شرکت رد می‌شوند. کاربران بیمه‌گر به بیمه‌گر مشخص متصل می‌شوند و ورود اطلاعات آن‌ها به شرکت‌های تحت پوشش قراردادهای فعال محدود می‌شود.

## وضعیت مهندسی و محدودیت‌ها

این پروژه هنوز برای داده واقعی سازمانی تأیید نهایی نشده است. CI ابتدا Migrationهای اولیه را برای ساخت پایگاه داده آزمایشی تولید می‌کند؛ این فایل‌ها در اجرای CI موقت هستند و خودکار به مخزن اضافه نمی‌شوند. قبل از نصب تمیز یا استقرار، Migrationهای تولیدشده باید بازبینی و در Git ثبت شوند. پس از دریافت تغییرات، دستورات `makemigrations`، `migrate`، `check` و `test` را اجرا و خروجی را بازبینی کنید.

موارد لازم پیش از بهره‌برداری واقعی:
1. تولید و بازبینی migrationها در محیط نصب‌شده؛ تغییرات مدل حساب کاربری و اپ‌های جدید نیازمند migration هستند.
2. پیاده‌سازی MFA واقعی، محدودسازی تلاش ورود، بازیابی حساب و سیاست انقضای نشست.
3. اسکن بدافزار و اعتبارسنجی کامل نوع واقعی فایل‌ها؛ بررسی امضا/ساختار و محدودیت اندازه/محتوای آرشیو اضافه شده، اما جایگزین اسکن بدافزار نیست.
4. تکمیل گردش‌کارهای چندمرحله‌ای بر اساس رشته بیمه و ماتریس رسمی تفویض اختیار.
5. افزودن صف پس‌زمینه برای فایل‌های حجیم، گزارش‌های مدیریتی پیشرفته و پایش خطاها.
6. آزمون نفوذ و تست دسترسی بین شرکت‌ها، بیمه‌گرها، کارکنان و داده‌های محرمانه.
7. استقرار با HTTPS، PostgreSQL، نسخه پشتیبان رمزگذاری‌شده و آزمون دوره‌ای بازیابی.

فایل‌های حساس باید فقط از مسیرهای دانلود احراز هویت‌شده دریافت شوند؛ فایل‌های پزشکی و اطلاعات غیرضروری حساس را در سامانه بارگذاری نکنید.
