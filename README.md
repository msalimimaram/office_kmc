# اداره بیمه — سامانه یکپارچه مدیریت بیمه

نسخه اولیه قابل توسعه Django برای پرتال اداره بیمه. این مخزن مستقل است و هیچ وابستگی به پروژه GAMva ندارد.

## امکانات موجود در اسکلت اولیه
- ورود کاربران و نقش‌های پایه سازمانی
- اطلاعات شرکت‌ها و بیمه‌شدگان و افراد تحت تکفل
- قراردادها، بیمه‌گران و رشته‌های بیمه
- فهرست خسارت‌ها با فیلتر دسترسی بر اساس نقش، شرکت و شخص
- ثبت اعتراض به خسارت
- ثبت و پیگیری درخواست‌های کارکنان
- وظایف داخلی
- بارگذاری اکسل خسارت با اعتبارسنجی پایه و مرحله تأیید نهایی
- ثبت رویدادهای حسابرسی برای چند عملیات حساس
- پنل مدیریت Django و رابط فارسی/راست‌چین

## نیازمندی‌ها
- Python 3.11 یا بالاتر (Python 3.10 نیز ممکن است با نسخه‌های سازگار اجرا شود)
- pip
- SQLite برای توسعه یا PostgreSQL برای محیط سازمانی

## اجرای محلی در Windows
```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
copy .env.example .env
python manage.py makemigrations accounts organizations insurance claims requests_portal tasks documents imports auditlog
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```
سپس نشانی `http://127.0.0.1:8000/` را باز کنید. در محیط توسعه، مدیر اولیه با دستور `createsuperuser` ساخته می‌شود.

## قالب اکسل خسارت
ردیف اول باید سرستون‌های انگلیسی دقیق داشته باشد:
- اجباری: `claim_number`, `national_id`, `service_type`
- اختیاری: `service_date`, `registered_date`, `requested_amount`, `assessed_amount`, `payable_amount`, `paid_amount`, `payment_date`

تاریخ‌ها را ترجیحاً به فرمت `YYYY-MM-DD` وارد کنید. شناسه خسارت تکراری در نسخه فعلی رد می‌شود و به‌روزرسانی امن و نسخه‌بندی رکوردهای موجود نیازمند پیاده‌سازی تکمیلی است.

## اجرای تست‌ها
```powershell
python manage.py test
python manage.py check
```

## ملاحظات مهم پیش از استفاده واقعی
این بسته یک **نمونه اولیه مهندسی‌شده برای شروع توسعه** است، نه محصول تأییدشده برای داده واقعی. قبل از استقرار:
1. تمام مهاجرت‌ها را تولید و بازبینی کنید.
2. سیاست نهایی نقش‌ها، دسترسی بیمه‌گر و دسترسی محرمانه درخواست کمک‌هزینه را با سازمان تطبیق دهید.
3. MFA واقعی، محدودسازی ورود، بازیابی حساب امن، مدیریت نشست‌ها، بررسی امنیت فایل‌ها و اسکن بدافزار را تکمیل کنید.
4. ذخیره فایل خصوصی را خارج از مسیر عمومی وب تنظیم کنید؛ در این نسخه فایل‌های درخواست در MEDIA_ROOT نگهداری می‌شوند و سرویس دانلود امن اختصاصی هنوز باید اضافه شود.
5. ثبت رویدادها را به تمام عملیات حساس گسترش دهید و سیاست نگهداری/دسترسی به لاگ‌ها را تعیین کنید.
6. برای فایل‌های اکسل، تأیید نهایی باید پس از بازبینی نمونه داده و تست‌های کارایی/حجم انجام شود؛ پردازش فعلی در یک درخواست وب انجام می‌شود و برای فایل‌های بسیار بزرگ باید به صف پس‌زمینه منتقل شود.
7. به‌طور پیش‌فرض فایل‌های پزشکی را بارگذاری نکنید. این سامانه برای نگهداری تصویر مدارک پزشکی یا انجام تراکنش مالی طراحی نشده است.
8. از کلید مخفی قوی و متغیرهای محیطی واقعی استفاده کنید؛ مقدار نمونه در تنظیمات فقط برای توسعه است.
9. آزمون نفوذ و تست‌های دسترسی بین شرکت‌ها و بین بیمه‌شدگان انجام شود.
10. برای تولید واقعی، از HTTPS، پایگاه داده سازمانی، نسخه پشتیبان و آزمون بازیابی استفاده کنید.

## وضعیت فعلی
رابط کاربری و مدل‌های پایه فراهم شده‌اند. پیش از بهره‌برداری واقعی، باید اجرای واقعی تست‌ها در محیط نصب‌شده، بازبینی مجوزها، تکمیل احراز هویت چندمرحله‌ای، مهاجرت‌ها، صف پردازش اکسل، دانلود امن فایل‌ها، گردش‌کارهای تأیید چندمرحله‌ای و گزارش‌های مدیریتی کامل شود.
